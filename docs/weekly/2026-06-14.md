## What changed

### Modeling
- **4 new leak-safe features (26 → 30 contract):** `static_inspection_type`,
  `prior_pass_w_conditions`, `prior_reinspections`, `prior_complaint_inspections`.
  Served (logreg + sigmoid, RT-filtered): **PR-AUC 0.299 → 0.315,
  precision@10% 0.338 → 0.352**.
- **XGBoost validation fix:** early stopping was watching the same validation
  set we scored on (a double-dip). It now early-stops on an embargoed tail of
  train, refits on full train at the fixed tree count, and validation is used
  only for calibration. Honest test (unfiltered, n=13,812): **PR-AUC
  0.254 → 0.268, log-loss 0.282 → 0.261**.
- **Production estimator:** XGBoost clears PR-AUC but misses precision@10%, so
  by our both-metrics gate the **logistic-regression baseline stays in
  production**.
- **Features tested and left out (flat):**
  - 311 spatial counts (PR-AUC 0.3147 → 0.3152)
  - operator / license-history features (0.3147 → 0.3151)
  - per-violation-type counts (codes 1–29): XGB 0.2681 → 0.2687, LogReg
    0.2660 → 0.2663 — the codes are already saturated by the priority/core
    rollups and keyword flags.

  Please don't re-try these without new data — the existing `prior_*` history
  already captures the signal. (Also found: `license_status` is uniformly `AAI`
  everywhere, so there's no revoke/closed signal to mine; `account_number` only
  exists in the current-license file.)

### Evaluation
- **Added recall@k** (top 5/10/20%) to the eval suite — every run now logs it.
  Served **recall@10% ≈ 0.33** (we catch about a third of real risks in the top
  decile). This adds new fields to every `reports/metrics/*.json`.
- **Time-based cross-validation** (`expanding_year_folds`, full-year, 180-day
  embargo) + 5 leakage-guard tests. Config is stable: PR-AUC 0.326 ± 0.029
  across 2020–2024. Sigmoid chosen over isotonic by mean Brier across folds.

### Tracking & docs
- **Served-model reconcile:** the served model now writes its own tracked
  metrics, so committed numbers match what's deployed (they used to describe a
  different, isotonic model).
- **Experiment tracking:** runs are versioned by content hash (`features_sha256`
  + `feature_set_version`), not by committing data; `reports/metrics/*.json` is
  the diffable ledger.
- **Decision records (new `docs/decisions/` practice):** 0001 (experiment
  tracking + served-model reconcile), 0002 (validation methodology), 0003
  (proposed Phase-2 tracking plan). 0001 also gained a note that the per-run git
  SHA is development-time only — permanent identity is `features_sha256`.
- **sklearn 1.9:** `cv='prefit'` was removed, so calibration now uses
  `FrozenEstimator`.

### EDA (merged earlier)
- Notebook 01 dataset overview + fixes: fail-rate math restricted to real
  outcomes (pass / pass-with-conditions / fail), violation counting via the
  numbered-code regex, outputs cleared (1.5 MB → 68 KB), added `uv.lock`, and
  gitignored JupyterLab temp files.

## One learning

If early stopping watches the same validation set you later score on, you're
tuning on your test data — the reported metric looks better than it really is.
The fix was to early-stop on an embargoed tail of train and reserve validation
for calibration only.
