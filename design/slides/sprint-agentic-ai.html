What was built

🤖

Agentic AI over HTTP Shipped

  • AWS Bedrock AgentCore Runtime hosts a Claude Sonnet 4.6 agent with access to Chicago inspection data and risk scores
  • Lambda proxy sits between the public ALB and AgentCore — signs all requests using the Lambda execution role (IAM SigV4), so AgentCore is never directly exposed
  • Lambda parses AgentCore's SSE streaming response into clean JSON text before returning to the browser
  • Session IDs (36-char UUID) preserved across turns for multi-turn conversation
💬

Chat UI Shipped

  • New /chat route in the Next.js app — added to the global navigation
  • Suggested query chips, auto-growing textarea, Shift+Enter for newlines
  • Session state in sessionStorage — cleared on "New conversation"
  • Graceful error states with terra-coloured warning bubbles
  • Disclaimer: "Scores are 180-day predictions from public Chicago data"
☁️

CloudFront CDN Deployment Shipped

  • Next.js static export (output: 'export') — no Node server needed
  • Top 500 highest-risk restaurant detail pages pre-generated at build time; lower-risk pages return 404 (chat covers discovery)
  • S3 bucket + CloudFront distribution with HTTPS enforcement, gzip compression, and 1h cache TTL
  • Custom 404 page wired up in CloudFront error response config
🔒

Auth & CORS Shipped

  • Mixed-content fix: CloudFront proxies /api/agent → ALB, so the browser always calls HTTPS and never touches the HTTP ALB directly
  • Lambda returns Access-Control-Allow-Origin: * and handles OPTIONS preflight requests
  • AgentCore protected behind IAM — only the Lambda execution role can call InvokeAgentRuntime; the ALB has no auth of its own
  • Upgrade path: Add Cognito User Pool to the ALB listener rule → pass JWT as Authorization: Bearer from the browser
⚠️

Current limitation: ML inference is stubbed

AgentCore's tool implementations today return estimated / heuristic scores — not predictions from the trained XGBoost model. The agent reads scores.json from S3 at warm-up, but that file currently contains mock data (is_mock: true) because the real model hasn't been run end-to-end and written to data/predictions/scores.parquet yet. All restaurant rankings, risk tiers, and SHAP driver text shown in chat responses are therefore illustrative, not real model output. The S3 IAM permissions for the AgentCore role also need to be finalised before the bucket read will succeed in all environments.

Next steps

Integrating real ML inference

STEP 01

Run the XGBoost pipeline end-to-end

Execute make all to produce data/predictions/scores.parquet with real risk scores, calibrated probabilities, and SHAP top-drivers from the trained model.

STEP 02

Publish real scores.json to S3

Run scripts/parquet_to_json.py to convert scores.parquet → scores.json, then upload to s3://food-safety-intelligence-data/web-app-data/. Fix AgentCore IAM role's s3:GetObject permission (currently blocked by org RCP).

STEP 03

Rebuild and redeploy the web app

Rerun npm run build inside app/ and sync out/ to S3. The static pages will embed real risk scores. Redeploy AgentCore so it loads the real scores on warm-up. Invalidate CloudFront.

STEP 04

Wire SHAP drivers into the agent

The agent's tool currently returns hard-coded driver text. Once scores.json has real top_drivers (from shap.TreeExplainer), update the tool to return the actual SHAP feature names and contribution values.

STEP 05

Tighten authentication

Move from CORS: * to Cognito JWT auth on the ALB listener. Restrict Access-Control-Allow-Origin to the CloudFront domain only. Consider rate-limiting at the ALB or API Gateway level.

STEP 06

Scheduled score refresh

Chicago posts new inspection data weekly. An EventBridge cron → Lambda → parquet_to_json.py → S3 upload keeps scores current without manual reruns. (Out of scope for this capstone iteration, but documented.)
