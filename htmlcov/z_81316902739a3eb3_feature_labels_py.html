1"""Feature presentation registry — ONE source of truth for how a feature reads. 

2 

3This module is pure text with no ML dependencies, so label consumers (the batch 

4scorer, the methodology builder, the modeling notebook) can import it without 

5pulling in numpy / pandas / sklearn via ``shap_drivers``. The attribution math 

6lives in ``shap_drivers`` and imports the registry from here. 

7 

8Each feature has two presentational forms, kept together so they can't drift: 

9 • ``name`` — a generic, value-free label for the GLOBAL feature-impact chart 

10 (model card / methodology page), which ranks features across the whole 

11 population, so there is no single value to show. 

12 • ``label`` — the PER-ROW driver label. Usually a ``{value}`` format template 

13 filled with the row's value; numeric features show the value, boolean 

14 keyword flags only render when True (the False case is suppressed at the 

15 caller), category features show the triggering category. 

16 

17A few binary OUTCOME features (e.g. ``was_fail``) read oppositely for the pass 

18vs fail case and surface in BOTH directions — a fail pushes risk up, a pass 

19pulls it down. A single template can't say both, so their ``label`` is a 

20``{True: ..., False: ...}`` dict chosen by the row's value at render time. 

21 

22The per-row labels are what end up on the restaurant detail page next to the 

23horizontal driver bars; they were tuned for the Clinical Quiet mockup's tone — 

24neutral, not alarmist. ``FEATURE_LABELS`` and ``display_name()`` below are 

25DERIVED from this registry, so the global and per-row views stay in sync. 

26"""

176def display_name(feature: str) -> str: 

177 """Plain-English, value-free name for a feature in the global chart; falls 

178 back to the raw key so a newly-added feature still renders (un-prettified).""" 

179 return FEATURES[feature].name if feature in FEATURES else feature
