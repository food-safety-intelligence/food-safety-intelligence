1"""Building permit / violation features via block-face spatial join. 

2 

3Physical-plant condition — old plumbing, failing refrigeration, structural 

4issues — is plausibly orthogonal to a venue's *inspection* history, which is 

5why building records are the first external-data bet for breaking the modelling 

6ceiling (the existing inspection / 311 / license feeds are mutually correlated 

7and exhausted). 

8 

9**Why block-face, not same-building.** Chicago building records are filed under 

10the building's street number, which often differs from the food 

11establishment's recorded number (e.g. a restaurant at "3107 N BROADWAY" with 

12its block's permits/violations recorded at 3109 / 3112 / 3115). Exact 

13street-number matching is therefore brittle (empirically ~40 % recall for 

14violations, ~2 % for permits). A tight lat/lon radius is the robust match — 

15but at ~30 m it captures the immediate block-face (this building plus its 

16nearest neighbours), not strictly one parcel. We deliberately keep the radius 

17tight: a wider radius (≥100 m) degrades into "is there any construction on this 

18block," i.e. neighbourhood density, which both dilutes the building signal and 

19reintroduces the geographic proxy we dropped ``static_zip`` to avoid. The 

20granularity here is **block-face**, and the group-fairness gate is non-optional 

21because of it. 

22 

23**Implementation** (mirrors ``complaint_features.add_complaint_features``): 

24 1. Build a ``sklearn.neighbors.BallTree`` over event (lat, lon) with 

25 ``metric='haversine'``. 

26 2. For each inspection anchor, ``query_radius`` returns the events within the 

27 block-face radius. 

28 3. Apply the date window and count / take recency. 

29 

30**Leak-free guard**: only events strictly BEFORE the anchor date count 

31(``event_date < as_of_date``). A permit issued or violation recorded ON the 

32inspection day is excluded — we never let same-day or future physical-plant 

33records inform a prediction whose label window starts after the anchor. 

34 

35**Cold-start / no-geo handling**: anchors with missing lat/lon get ``NA`` for 

36every column — "we couldn't compute a spatial signal", not a fabricated 0. 

37``days_since_*`` is also ``NA`` when the venue's block-face has no prior record 

38at all, so the model can tell "no history" from "yesterday". 

39 

40**Bureau-specific features**: when the violations dataframe includes a 

41``department_bureau`` column, ``add_building_features`` also computes per-bureau 

42violation counts for the five bureaus directly tied to food-safety risk: 

43 

44 * ``CONSERVATION`` — structural / pest / plumbing (1.3M rows, highest density) 

45 * ``REFRIGERATION`` — commercial refrigeration failures (direct food-safety risk) 

46 * ``PLUMBING`` — hot water supply and drainage (tied to food-inspection codes) 

47 * ``VENTILATION`` — kitchen exhaust systems 

48 * ``ELECTRICAL`` — power failures that cascade to refrigeration failures 

49 

50These produce ``prior_bldg_{bureau}_365d`` columns plus a combined 

51``days_since_last_food_safety_bldg_violation`` recency across all five bureaus. 

52The single-window design (365d) is intentional for the sparse bureaus (32–43k 

53rows city-wide): 730d risks picking up violations from a previous tenant or a 

54prior building on the site. 

55"""

103 """Append block-face building-permit / violation features to inspections. 

104 

105 Produces, for the block-face within ``radius_m`` of each anchor and strictly 

106 before its date: 

107 

108 **Aggregate violation features** (always, when violations is not None): 

109 * ``prior_bldg_violations_365d`` / ``prior_bldg_violations_730d`` (Int32) 

110 * ``days_since_last_bldg_violation`` (Float64; NA = no prior on block-face) 

111 

112 **Bureau-specific features** (when violations has a ``bureau_col`` column): 

113 * ``prior_bldg_{bureau}_365d`` for each bureau in ``food_safety_bureaus`` 

114 (one 365d count per bureau; slug = bureau.lower().replace(" ", "_")) 

115 * ``days_since_last_food_safety_bldg_violation`` (Float64) — recency of 

116 ANY violation from a food-safety-relevant bureau 

117 

118 **Permit features** (when permits is not None): 

119 * ``prior_bldg_permits_365d`` (Int32) 

120 * ``days_since_last_bldg_permit`` (Float64) 

121 

122 Args: 

123 inspections: must contain ``inspection_date``, ``latitude``, 

124 ``longitude``. 

125 permits: Building Permits dataframe (``issue_date`` + ``latitude`` / 

126 ``longitude``). If ``None``, the permit columns are skipped. 

127 violations: Building Violations dataframe (``violation_date`` + 

128 ``latitude`` / ``longitude``). If ``None``, the violation columns 

129 are skipped. 

130 radius_m: block-face search radius in metres. 

131 bureau_col: column in ``violations`` holding the bureau name. When 

132 absent from violations, bureau-specific features are skipped. 

133 food_safety_bureaus: bureau names to compute individual count features 

134 for. Defaults to ``FOOD_SAFETY_BUREAUS``. 

135 

136 Anchors with missing lat/lon get ``NA`` for every column (no spatial signal 

137 computable); building rows without geo are dropped before the tree build. 

138 """

213def _add_bureau_features( 

214 out: pd.DataFrame, 

215 violations: pd.DataFrame, 

216 has_geo: np.ndarray, 

217 anchor_coords_rad: np.ndarray, 

218 anchor_dates: np.ndarray, 

219 radius_rad: float, 

220 bureau_col: str, 

221 food_safety_bureaus: tuple[str, ...], 

222) -> None: 

223 """Add per-bureau violation counts + combined food-safety recency in-place. 

224 

225 Builds one BallTree per bureau (subset of violations) and calls 

226 _block_face_stats. Mutates ``out`` directly to avoid extra copies. 

227 """ 

228 date_col = "violation_date" 

229 fs_recency_col = "days_since_last_food_safety_bldg_violation" 

230 

231 # Initialise all output columns to NA before filling with-geo rows. 

232 for bureau in food_safety_bureaus: 

233 slug = bureau.lower().replace(" ", "_") 

234 count_col = f"prior_bldg_{slug}_365d" 

235 out[count_col] = pd.array([pd.NA] * len(out), dtype="Int32") 

236 out[fs_recency_col] = pd.array([pd.NA] * len(out), dtype="Float64") 

237 

238 # Shared geo + date prep for the full violations frame. 

239 ev_all = violations[["latitude", "longitude", date_col, bureau_col]].copy() 

240 ev_all["latitude"] = pd.to_numeric(ev_all["latitude"], errors="coerce") 

241 ev_all["longitude"] = pd.to_numeric(ev_all["longitude"], errors="coerce") 

242 ev_all[date_col] = pd.to_datetime(ev_all[date_col], errors="coerce") 

243 ev_all = ev_all.dropna(subset=["latitude", "longitude", date_col]) 

244 if ev_all.empty: 

245 return 

246 

247 # Per-bureau 365d count. 

248 for bureau in food_safety_bureaus: 

249 slug = bureau.lower().replace(" ", "_") 

250 count_col = f"prior_bldg_{slug}_365d" 

251 

252 ev_b = ev_all[ev_all[bureau_col] == bureau] 

253 if ev_b.empty: 

254 continue 

255 

256 counts, _ = _block_face_stats( 

257 event_coords_rad=np.radians(ev_b[["latitude", "longitude"]].to_numpy(dtype=np.float64)), 

258 event_dates=ev_b[date_col].to_numpy(dtype="datetime64[D]"), 

259 anchor_coords_rad=anchor_coords_rad, 

260 anchor_dates=anchor_dates, 

261 radius_rad=radius_rad, 

262 windows=(365,), 

263 ) 

264 out.loc[has_geo, count_col] = pd.array(counts[365], dtype="Int32") 

265 

266 # Combined food-safety recency: days since the nearest prior violation from 

267 # ANY of the five bureaus. One BallTree over the union — cheaper than five 

268 # separate recency queries and gives the model a single "how long since 

269 # any relevant building issue" signal. 

270 ev_fs = ev_all[ev_all[bureau_col].isin(food_safety_bureaus)] 

271 if not ev_fs.empty: 

272 _, recency = _block_face_stats( 

273 event_coords_rad=np.radians( 

274 ev_fs[["latitude", "longitude"]].to_numpy(dtype=np.float64) 

275 ), 

276 event_dates=ev_fs[date_col].to_numpy(dtype="datetime64[D]"), 

277 anchor_coords_rad=anchor_coords_rad, 

278 anchor_dates=anchor_dates, 

279 radius_rad=radius_rad, 

280 windows=(365,), # windows arg required; recency is window-independent 

281 ) 

282 out.loc[has_geo, fs_recency_col] = pd.array(recency, dtype="Float64")

290def _block_face_stats( 

291 event_coords_rad: np.ndarray, 

292 event_dates: np.ndarray, 

293 anchor_coords_rad: np.ndarray, 

294 anchor_dates: np.ndarray, 

295 radius_rad: float, 

296 windows: tuple[int, ...], 

297) -> tuple[dict[int, np.ndarray], np.ndarray]: 

298 """Per-anchor block-face counts (one per window) + days-since-last. 

299 

300 One BallTree build + radius query, then a per-anchor date pass. For each 

301 anchor we take the ages (in days) of all events within the radius, keep only 

302 those strictly before the anchor (``age > 0`` — the leak guard), count those 

303 within each window, and take the minimum positive age as recency. 

304 """ 

305 tree = BallTree(event_coords_rad, metric="haversine") 

306 neighbour_indices = tree.query_radius(anchor_coords_rad, r=radius_rad) 

307 

308 n = len(anchor_coords_rad) 

309 counts = {w: np.zeros(n, dtype=np.int32) for w in windows} 

310 recency = np.full(n, np.nan, dtype=np.float64) 

311 

312 for i, idxs in enumerate(neighbour_indices): 

313 if len(idxs) == 0: 

314 continue 

315 # Age in days from event to anchor; positive = strictly before the 

316 # anchor date (the leak guard — same-day and future events excluded). 

317 ages = (anchor_dates[i] - event_dates[idxs]).astype("timedelta64[D]").astype(np.int64) 

318 prior = ages[ages > 0] 

319 if prior.size == 0: 

320 continue 

321 for w in windows: 

322 counts[w][i] = int((prior <= w).sum()) 

323 recency[i] = float(prior.min()) 

324 

325 return counts, recency
